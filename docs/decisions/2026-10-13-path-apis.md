# Path APIs over string handling

## Context

Issue #44's fix walked a doc path's ancestors by splitting on `/` and rejoining. The maintainer
asked that path handling use APIs that behave correctly across platforms, since contributors and
agents also run the repo on Windows.

## Decision

Manipulate paths with `node:path`, never by splitting, joining, or slicing strings. Pick the flavor
by where the path lives: the default (platform) functions for filesystem paths, and `path.posix` for
paths that are `/`-separated on every platform, such as repo-relative paths in docs, git pathspecs,
URLs, and zip entry names.

## Alternatives

Hand-rolled string handling reads fine on macOS & Linux but breaks on `\` separators, drive letters,
and `.` or `..` segments. Normalizing everything to platform paths would corrupt git pathspecs and
zip entries on Windows.

## Revisit if

The repo drops Windows support, or a dependency offers a typed path abstraction worth adopting
across scripts.
